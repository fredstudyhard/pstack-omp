### Shipping

Read [the OMP runtime contract](../references/omp-runtime.md) first, [the main entrypoint](../SKILL.md), and [Merge and restack safety](../references/merge-safety.md) before any merge, arm or topology operation.

**Land only the independently verified contiguous run from the bottom.** Existing explicit landing authority, service protection and independent revision-bound proof are all required. Babysit/status or a green PR is not that authority. Verify destination repository, branch and identity before writes.

1. **Resolve forge and verify each PR independently.** Default to `gh`; use installed working `origin pr` only when it resolves the approved target and provides the required safety capabilities, recording fallback. Capture the chain bottom-to-top, branch names, head/base SHAs, destination and original parent boundary. Leave unrelated PRs alone. Resolve `<poteto-dir>` to the absolute directory `skills/poteto-mode` containing this loaded playbook directory. The shipped GitHub safety helper is `<poteto-dir>/scripts/watch-pr/ship-pr`.

   Run `<poteto-dir>/scripts/watch-pr/ship-pr inspect --repo <owner/repo> --pr <n>` and save its JSON as a named evidence record using approved tooling. Before long review, cancel an unverified pending merge only with cancellation authority, via `<poteto-dir>/scripts/watch-pr/ship-pr cancel-pending --record <record.json>`, then read back. No cancellation authority means hold and escalate, not leave an unsafe request claimed safe.

   A fresh configured native reviewer who did not author the change verifies parent versus head on the actual user surface in isolated output/worktree. Record PASS, PASS+NOTES or FAIL, author and actual identity, head SHA, base SHA/branch, stable `git patch-id`, exact commands and receipts. Post to the PR only with remote-write authority; local evidence is not a forge-enforced approval. Missing required reviewer/family is BLOCKED; tests, author proof and advisors cannot substitute.
2. **Select the contiguous verified run.** Starting at the lowest unmerged PR, stop at the first without an applicable PASS/PASS+NOTES. Everything above waits. An independent upper patch can move to trunk only under topology authority and with fresh context verification.
3. **Reassess applicability.** A verdict covers its patch and dependencies, not just a SHA. Compare stable patch-id at verdict/current revisions. Identical patch-id retains review only after checking destination/dependency applicability; uncertain context requires re-verification. Test/docs/lint-only drift can preserve a live lane only if its generated behavior is demonstrated equivalent at both revisions apart from measured nondeterministic or embedded-SHA noise. Name each noisy file and evidence. A lane without comparable build output reruns. New changes still need their own checks and review; every new head needs current CI and mergeability.
4. **Land one bottom PR at a time under a server head guard.** Immediately confirm the intended base, then on GitHub use `gh pr merge <n> --repo <owner/repo> --squash --match-head-commit <verified-head>`. This guards head, not base. Coordinate the sole topology writer and observe the base before/after; do not claim atomic base protection. Origin is usable for merge only after proving an equivalent service-enforced expected-head condition; its plain merge can land lower PRs as well, so never infer parity. Otherwise stop at merge-ready.

   Read back state, final head, base, merge time and non-null merge commit. A success exit, queued admission or auto request is not a merge. Fetch the authorized destination and prove the merge commit is an ancestor, then inspect resulting content before advancing. A PR still based on a parent branch does not count as landed to trunk.

   Auto-merge or required queue admission is allowed only under existing repository rules enforcing the required verdict and CI for the eventual revision/context, not a prose verdict on an older head. Never use `--admin`, loosen protection or bypass a required queue. If service guarantees cannot be established, stop at the unmet gate.

   Before any affected push, rebase or base edit, inspect and cancel pending mechanisms for every affected descendant using the safety helper. Only exit 0 with `kind: cancelled` permits the operation. `changed`, `not-open`, `still-pending`, `unavailable`, unknown state or a concurrent merge requires reconciliation, not overwriting the evidence record to bypass it. The helper is GitHub-only; Origin needs its own proven equivalent.

   After confirmed parent squash, retarget the next child to trunk only within authority. In its clean exclusive worktree validate recorded old parent tip is an ancestor and `old-parent..child` contains only child work, then replay with `git rebase --onto <trunk-tip> <old-parent-tip> <child-branch>`. Capture the exact remote ref SHA before rewriting and publish only with an authorized `--force-with-lease=refs/heads/<child>:<captured-remote-head>`. A lease failure means reconcile concurrent work, never refresh-and-overwrite. Preserve `.omp` and unrelated data. Step 3 governs surviving verdicts; rerun applicable checks.
5. **Freeze other writers during landing.** Only step 4's sanctioned child movement may change the chain. For GitHub monitor with `<poteto-dir>/scripts/watch-pr/watch-pr --owner <owner> --repo <repo> --queued-stack --stack-prs <frozen-bottom-to-top-list> --interval 60 --timeout <remaining-positive-seconds>`, within an owned supervised segment and captured process handle. For Origin use bounded one-shot view/check reads at the declared cadence. No detached watcher, wake loop or extra sleep layer.

   Reinspect landing head/base against approved evidence after each state change; cancel invalid pending requests within authority. Preserve helper BLOCKER reasons: conflicts/behind-base to topology owner, threads/CI to PR owner, approval to operator. Do not rearm unchanged blockers. WAITING/merge-queue is not complete. TIMEOUT/status-query means unknown, never merge permission. Segment expiry checkpoints actual state and next command using [Pause safely](pause-safely.md), without claiming the ceiling landed.
6. **Stop at the ceiling.** Confirm the selected run is merged into the intended destination. Extending it requires new verdicts and authority, not automatic upward progress.

**Reply:** run and ceiling, per-PR reviewer and revision-bound verdict, actions armed/cancelled and read back, confirmed landings and ancestry proof, unresolved service limits/gates and next gap.
