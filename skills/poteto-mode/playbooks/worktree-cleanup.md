### Worktree and simulator cleanup

Read [the OMP runtime contract](../references/omp-runtime.md) first and [the main entrypoint](../SKILL.md).

**Cleanup can destroy unique user state. Audit is not deletion authority.** Preserve all `.omp` paths and unrelated data. General cleanup never authorizes deleting/moving `.omp`, even inside a disposable-looking worktree; that requires exact path/operation authorization.

1. Snapshot `df -h /` and audit the named repository. Resolve the shipped helper relative to this loaded file as the absolute `skills/poteto-mode/scripts/worktree-audit.mjs`, then run `node <absolute-helper> <repository>` for local read-only facts. It derives candidates from `git worktree list`. Do not guess worktree locations. Optional transcript arguments must be explicitly named authorized files, never user-home discovery or a recursive scan; only use `--online` when network reads/fetch are authorized. Run a slow audit as a bounded owned job, not a detached mystery process.
2. Buckets are evidence, not permission. Cross-check the operator's pinned/in-use trees and explicitly supplied current-session agent/process ownership. A safe bucket cannot override a pinned chat, live writer, protected `.omp`, lock or unknown fact. No session scan is necessary to invent certainty.
3. Investigate doubtful/recent-chat candidates using only supplied current-session `history://<id>`/`agent://<id>` or named authorized exports. Read-only bounded scouting may partition explicit artifacts under host rules. A pinned parent may own sibling repro/arena trees; absence from a session title does not prove unused. Unknown usage means hold.
4. Inventory all loss before approval. Read `git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none`, `git -C <path> status --porcelain --ignored=matching`, task-relevant diff including submodules, branch reachability and reflog. Explain `wip:N`, `untracked:N`, non-disposable `ignored:N` and reflog-only commits. An empty tracked diff does not cover untracked/ignored files. Inspect changed submodules internally; their unique commits and files can disappear with the worktree. Retain reachable refs for unique commits only under authority. Locked trees remain locked, never use recursive deletion to bypass a refusal. Show exact affected paths and losses; obtain deletion authorization matching that set. Dirty, unknown, in-use, locked or protected candidates stay held unless their exact operation is explicitly authorized and safe.
5. Remove only the approved set using `git worktree remove <exact-path>` without force by default. If Git refuses because data remains, stop and reconcile; never fall back to `rm -rf`, hard reset or delete ignored files because they look rebuildable. A worktree containing any `.omp` path is not removable under a generic prune grant. Preserve branches/refs and artifacts needed for resume, then `git worktree prune` only for stale administrative records within approved scope. Re-list worktrees and record `df -h /` after actual authorized removal.
6. Other reclaimers are separately named candidates, not automatic targets. Inspect local simulator/runtime inventory with `xcrun simctl` before suggesting specific unavailable devices or runtime IDs. Delete only approved exact IDs; never blanket `delete all`. Xcode DerivedData/DeviceSupport or package caches require the same ownership/loss/authority analysis. User-home agent transcripts, shell snapshots, credentials and configuration are not caches for this workflow; do not scan or delete them.

**Reply:** before/after disk evidence and actual reclaimed space, exact removals and authorization scope, each held tree with its reason/owner or unknown fact, and any protected `.omp` boundary. If audit-only, report candidates without pretending space was reclaimed.
