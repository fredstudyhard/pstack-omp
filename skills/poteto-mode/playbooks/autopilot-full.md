### Autopilot-full

Read [the OMP runtime contract](../references/omp-runtime.md) first and [the main entrypoint](../SKILL.md) for native drivers, roles and authority.

**One owner carries each independent PR from build to merge-ready. The root owns independent verdicts. The operator owns every merge.** A verdict covers a patch/context; CI covers a head. No name such as autopilot grants external writes or unlimited execution.

1. **Frame the authorized queue and gates.** A plan request is not execution authority. Preserve the operator's item list, exclusions, done predicate and operator-only actions in standing orders and native todo. Identify owner count, verifier scenarios, explicit call/dispatch/time ceiling, cost drivers and fix rounds before dispatch. Obtain an existing applicable provider budget/plan before billed work. Without another approved limit, use the runtime's two-worker, one-review, one-correction, 15-minute supervised segment defaults. A specifically approved larger program may allow at most two fix-forwards per PR; do not silently inflate the default to that ceiling. Expiry preserves pending work, not a false completed queue.
2. **Assign one owner and durable location per PR.** Resolve forge once (`gh` by default or approved working `origin pr`, no required Graphite). Give each configured native implementation worker an explicit exclusive worktree and base revision. In `tasks[]`, `task` contains original requirements, owned paths, acceptance, forbidden operations, output/evidence path and finite lifecycle; `solutionSpace` states only degrees of freedom, and `context` carries shared facts. No invented background/isolation/model/resume fields.

   The owner builds, obtains required design review, performs `/skill:pstack-deslop` and `/skill:pstack-no-comments`, proves the integrated actual behavior and runs [Opening a PR](opening-a-pr.md) only with the queue's explicit creation/push grant. Opening early is useful for CI only within that grant; missing independent review never becomes merge-ready. The lifecycle may explicitly assign finite [Babysit](babysit.md); otherwise opening does not start it. No owner merges.

   Before the code-ready report, the topology owner prepares the approved base and records head/base; fixes stay on that base unless conflicts or real base drift require re-preparation. Run project checks on the integrated committed head before an authorized PR-facing push, not against other active writers. Every later head is reported and gets applicable checks/current CI.

   Persist a sanitized decision trail, owner ID/role, process handle, worktree, branch, base/head, artifact path, last observed progress and stuck-after threshold under `<repository>/.audit/pstack/<task>/`. Record local artifacts immediately; push durable branch checkpoints only under push authority. A task can survive session loss via files and branches, not a cold agent URI. Any authorized rewrite uses the captured exact remote SHA and [merge safety](../references/merge-safety.md), never an implicit lease or blind retry after another writer's push.
3. **Keep independent PRs independent.** Branch off their approved trunk revision, not one another. Coupled/ordered work routes to [Autopilot-stack](autopilot-stack.md). Dispatch genuinely independent slices together only under host rules and the concurrency ceiling. A leaf does not spawn nested workers.
4. **Independently verify finished code.** Read `/skill:pstack-swarm`. Run the full scenario/coverage matrix once at code-ready and again for substantial new behavior/redesign/diff. Use bounded batches or sequential fresh reviewers without dropping coverage; a rebase, conflict resolution or small correction gets an applicable fresh independent check at the new revision. Required identity/family must be proven from actual host records. Missing independence leaves BLOCKED, never author/advisor substitution.

   Reviewers rerun relevant gates, drive load-bearing behavior on the real surface and audit diff plus receipts, not the PR body's claims. Each reports what this diff breaks, not every pre-existing issue. Do not add mutation/fuzz campaigns without a request. A defect reproduced on trunk alone is recorded separately; one copied/newly reached by this patch remains its responsibility.

   Batch proven findings into one owner correction with red-first evidence at all affected sites. The parent never races the branch's writer. Review the corrected revision within the remaining approved round budget. If a blocker survives the final authorized round, stop that PR with evidence and continue unrelated items. Do not silently narrow the PR, close it, buy another round or declare a note nonblocking merely to finish.
5. **Handoff only the tested landing context.** Before merge-ready, inspect current trunk and assess whether drift affects patch, callers, dependencies or check selection. Conflict/shared touched files or changed checks require base repair and fresh relevant proof. Caller/dependency drift requires merge-result checks. A changed lockfile may avoid another rewrite only when a frozen install proves the actual merge result and intended dependency versions; a failure requires repair. Unrelated drift need not cause an endless rebase loop. A third colliding preparation after merge prep is held for root sequencing rather than restart churn.

   Bind verdict to head/base/branch/patch-id and use [Shipping](shipping.md)'s applicability rule. Current CI and self-proof are necessary but not independent verdicts. The owner reports merge-ready with pinned head, receipts and remaining operator gates, then returns; a fresh owner takes the next item. Only the operator clicks merge. Autopilot-full does not itself authorize Shipping.
6. **Supervise the root layer within finite segments.** Gate relaxation, budget increases or allowlist changes require existing authority, independent evidence and fresh root countersign. A countersign cannot bypass forge approval or protection. Never disable/soft-fail checks to get green; repair causal failures under scope or block.

   At each result, phase boundary or planned audit cadence, reread this playbook and standing objective; inspect every known owner/leaf through supplied `agent://`, `history://`, process handles, branch/artifact evidence and ledger. Do not use status text alone, broad home scans or an hourly cloud wake service. Between useful events use native `wait` only with owned pending work and nothing else to do. External waits have finite attempts, cadence normally at least 60 seconds and an owned deadline. No hidden keep-alive or extra polling loop.

   Missing rows/heads are record drift, not automatically a dead agent. A stalled agent is one with observed failure or no evidence beyond its recorded threshold, excluding an explicit wait on root/operator. Stop or fence the old writer and confirm exclusive ownership before replacing; if termination is unavailable, use a separate read-only/isolated recovery and do not race its branch. On segment expiry use [Pause safely](pause-safely.md), preserving all pending owners and exact resume commands. Native host state is not cross-session persistence.
7. **Honor hold immediately.** Send every owned active worker a zero-writes order with native `write agent://<id>`, stop only captured run-owned processes, preserve outputs and report unconfirmed stops. Release requires the operator's applicable go; no merge happens because an old watcher wakes.

**Reply:** use `/skill:pstack-ketchup` to report each actual PR's state, pinned revision and verdict, what is ready for operator merge, countersigns and reasons, open gates, limits/stop reason, and explicit trail/checkpoint links. Never claim parent acceptance from worker output alone.
