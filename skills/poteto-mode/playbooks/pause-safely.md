### Pause safely

Read [the OMP runtime contract](../references/omp-runtime.md) first and [the main entrypoint](../SKILL.md).

**Leave a checkpoint a cold-start agent can resume.** Use for an explicit pause or required safety/budget/session boundary. A request to keep going means continue within the grant and finite segment, not bypass those boundaries.

1. Finish the current safe atomic step or preserve its exact partial state. Start nothing new. Send a zero-writes order to owned active agents through native `write agent://<id>`; cancel/stop owned work using actual host controls and captured handles. Record any unconfirmed stop, and fence that writer before replacement.
2. Do not push, create a PR, merge, deploy or delete merely to pause. Retain existing local work and unrelated data. Never delete or move `.omp`.
3. Make edits durable within current authority. If commits are authorized, a clearly scoped `wip:` commit may preserve this task's files, with a broken-tree warning if needed. Otherwise retain on-disk edits and save a named task-only patch/artifact when useful. Never stage unrelated changes or reset the tree for tidiness.
4. Write `<repository>/.audit/pstack/<task>/checkpoint.md` or the explicitly authorized durable handoff path. Include goal and original acceptance, completed/pending items, decisions and attribution, base/head/branch/worktree, observed verification versus NOT_RUN, active processes/ownership, remaining budget and stop conditions, linked artifacts, exact next command and resume entrypoint `/skill:pstack-poteto-mode resume <checkpoint-path>`. Preserve no credentials, provider state or raw private transcripts. Link an existing decision trail instead of duplicating it. The user must be told the explicit checkpoint path; portable means the note and linked files travel together, not that cold-session agent URIs work.
5. Preserve all specifically requested questions/checklists/procedures in the original order and wording when required, link each from the checkpoint and ensure every requested item is reachable. Optional same-machine locator: run `node <absolute-pstack-root>/skills/poteto-mode/scripts/resume.mjs begin --project <repository>`, write a locator copy of the note in the returned directory, then `publish --project <repository> --note <locator-note> --artifact <linked-file>` (repeat `--artifact` for every local link). Rebase the locator copy's links to absolute local destinations; copying relative links unchanged would point at the wrong files. Keep the portable primary note's links relative to its traveling artifact tree. Use inline Markdown links and register every local destination, including the primary checkpoint if linked. Invoke the full helper path with `node` for every operation. Read back with `read --project <repository>`. Its Git-local pointer does not replace the portable checkpoint. Inspect note and artifact completeness before claiming a usable handoff.

**Reply:** safe stopping point, on-disk paths and ownership, authorized commits or retained edits, known verification limits, unresolved active processes and the first resume action. This is a paused task, not completed acceptance.
