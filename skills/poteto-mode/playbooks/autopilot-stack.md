### Autopilot-stack

Read [the OMP runtime contract](../references/omp-runtime.md) first, [the main entrypoint](../SKILL.md) and [Autopilot-full](autopilot-full.md) in full. Its native owner lifecycle, finite budgets, independent review, checkpoints and hold rules apply; this playbook wins only for topology/delivery differences.

**Own the chain, never the landing.** Deliver one linear base-chained reviewed stack for the operator. No wake service or merge authority is implied.

1. **Owners report STACK-READY.** A dependent item branches from its parent's exact recorded tip, not trunk. Owners do not rebase, retarget, merge, close or arm auto-merge. The root owns topology and the operator owns landing. Each owner writes only its explicit exclusive worktree/branch, subject to publication authority and the full native task brief; `solutionSpace` is only concise degrees of freedom.
2. **One topology writer.** Owners report head and intended parent. Only the root's designated topology owner appends, rebases or retargets in dependency order. With explicit remote-write authority, use `gh pr edit <pr> --base <parent-branch>` or the approved Origin equivalent, never require Graphite. Read [Merge and restack safety](../references/merge-safety.md) before a rewrite. Capture the affected chain and exact remote heads, inspect/cancel pending auto-merge and queue membership for every affected PR, require a verified cancelled result, and publish only with an explicitly authorized `--force-with-lease=refs/heads/<branch>:<captured-remote-head>`. Lease failure means reconcile, not overwrite. The shipped GitHub helper resolves to the absolute loaded `skills/poteto-mode/scripts/watch-pr/ship-pr`; it is not an Origin implementation. If cancellation, authority or exclusive ownership cannot be established, hold topology. Owners take the reported new root revision as base and resolve only their slice for integration.
3. **Absorb drift at the root before delivery.** Apply Autopilot-full's landing-context analysis bottom-up, not on every irrelevant trunk move. Each link's base is its parent. Record head SHA, base SHA/branch and stable patch-id. Use [Shipping](shipping.md)'s applicability rule; changed or uncertain context returns to independent verification. New heads require current relevant checks/CI. Never test against active competing writer edits.
4. **Deliver, then freeze.** Each authorized PR carries its real revision-bound evidence or links to the named local record. Required unavailable independence leaves BLOCKED, not STACK-READY. Once landing begins, nobody changes the chain except the sanctioned post-parent-merge retarget/replay owned by Shipping. Mid-landing fixes wait for the operator's go and a revised evidence record. Segment limits produce `<repository>/.audit/pstack/<task>/checkpoint.md` with topology, pending items, limits and exact next command; the operator explicitly resumes under OMP.

Choose Autopilot-full for independent items handed off individually; choose this for sequenced/coupled work or one chain delivered for operator review. Both leave merge to the operator unless a separate explicit Shipping assignment grants it.
