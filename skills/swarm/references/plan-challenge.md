# Optional bounded work-order challenge

Use before execution only for an explicit adversarial plan review or a multi-step work order with material ambiguity or risk. Routine clear tasks do not need this gate, an extra reviewer, or cross-model consensus.

The parent uses the existing project task artifact and sets a finite review/revision limit before requesting a configured bounded reviewer. Limit the challenge to contradictions, unverifiable acceptance, missing prerequisites/dependencies, and scope or authority gaps. Do not turn it into an unrelated design or repository audit.

The parent resolves findings against evidence, revises the work order, retains material dissent, and gives workers the approved revision with acceptance criteria. Model agreement does not establish acceptance. Unresolved safety, authority, prerequisite, or acceptance blockers stop affected execution. Exhausting the review limit leaves unresolved blockers explicit; it does not authorize more rounds automatically or lower the gate.

If scope, dependencies, acceptance, or side effects materially change, pause affected work for a new parent decision and challenge only that changed boundary when needed. Unaffected independent work may continue within its contract. This gate grants no remote issue/PR write, push, deployment, or merge authority.
